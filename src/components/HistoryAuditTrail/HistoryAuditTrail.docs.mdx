<Description>
  `HistoryAuditTrail` renders an activity history list from a backend response. It supports empty
  and loading states, a panel close callback (`onClear`), row click handling (`onItemClick`), quick
  search, optional CSV/Excel export actions, multi-module filtering via source paths, and two
  rendering modes: `panel` (default) and `inline`.
</Description>

## Import

```ts
import { HistoryAuditTrail, HISTORY_AUDIT_RENDER_MODES } from '@gen2fund/gen2verse-ui-library';
import type { HistoryAuditTrailEvent } from '@gen2fund/gen2verse-ui-library';
```

## Basic usage

```tsx
import { HistoryAuditTrail, HISTORY_AUDIT_RENDER_MODES } from '@gen2fund/gen2verse-ui-library';
import type { HistoryAuditTrailEvent } from '@gen2fund/gen2verse-ui-library';

const events: HistoryAuditTrailEvent[] = [
  {
    id: '1',
    username: 'Alice Smith',
    auditEventType: 'ADDED',
    subject: "Added new derived field 'Net_Contribution'",
    details: 'Gross_Contribution - fees',
    timestamp: '2026-02-03T13:16:35.9275039+02:00',
  },
];

export function Example() {
  return (
    <HistoryAuditTrail
      renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}
      title="Activity History"
      countLabel={`${events.length} events`}
      events={events}
      onClear={() => {}}
      onItemClick={() => {}}
    />
  );
}
```

## States

- **Loading**: set `loading={true}` (and typically `events={[]}`) to show the loader.
- **Empty**: pass `events={[]}` to show the empty state.
- **Render mode**: use `renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}` (default) or
  `renderMode={HISTORY_AUDIT_RENDER_MODES.INLINE}`.

## Render modes

- **Panel mode (`renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}`)**: shows history icon, title,
  count badge, module dropdown (when multi-module), search, export, and close button.
- **Inline mode (`renderMode={HISTORY_AUDIT_RENDER_MODES.INLINE}`)**: shows module dropdown (when
  multi-module), search, export, and timeline grid only (no panel header/title/close button).
- The count badge automatically formats as `X of Y events` when filters reduce visible rows.
- `onClear` is intended for panel close handling (for example, parent hides the panel).

## Export-enabled usage

```tsx
import { HistoryAuditTrail } from '@gen2fund/gen2verse-ui-library';
import type { HistoryAuditTrailEvent } from '@gen2fund/gen2verse-ui-library';

const events: HistoryAuditTrailEvent[] = [
  {
    id: '1',
    username: 'Alice Smith',
    auditEventType: 'ADDED',
    subject: "Added new derived field 'Net_Contribution'",
    details: 'Gross_Contribution - fees',
    timestamp: '2026-02-12T09:43:12.9275039+02:00',
  },
];

export function ExportExample() {
  return (
    <HistoryAuditTrail
      title="Activity History"
      countLabel={`${events.length} events`}
      events={events}
      enableExport
      exportFileName="history-audit-trail"
    />
  );
}
```

When `enableExport` is enabled:

- Right-click on an activity/timestamp cell to open `Export` submenu (`CSV Export`, `Excel Export`)
- Click the download icon next to search to export directly to `Excel`

## Multi-module usage

```tsx
import { HistoryAuditTrail } from '@gen2fund/gen2verse-ui-library';

const moduleSources = [
  '/capevent/package/10001',
  '/capevent/configuration/1004',
  '/capevent/driver-report/3521',
];

export function MultiModuleExample() {
  return (
    <HistoryAuditTrail
      title="Activity History"
      events={events}
      countLabel={`${events.length} events`}
      moduleSources={moduleSources}
      primaryModuleSource="/capevent/package/10001"
    />
  );
}
```

Multi-module behavior:

- Dropdown appears only when more than one module has events
- Dropdown item names are derived from source paths (for example, `configuration` -> `Configuration`)
- `All Modules` shows all events across configured sources
- Secondary module entries show color-coded badges; primary module entries do not
- Change rendering supports both `oldValue/newValue` and `fieldChanges[]` response formats

### `moduleFilterCallback` behavior

`moduleFilterCallback` is optional. By default, filtering is automatic and uses:

```ts
event.source === selectedSource;
```

Provide `moduleFilterCallback` only when your event source format needs custom matching
(for example, trimming trailing slashes, normalizing case, or mapping aliases).

```tsx
moduleFilterCallback={(event, selectedSource) =>
  (event.source ?? '').replace(/\/$/, '').toLowerCase() ===
  selectedSource.replace(/\/$/, '').toLowerCase()
}
```

### `onModuleSourceChange` behavior

Use `onModuleSourceChange` to react when users change the module dropdown selection.
This is useful for syncing selected module state with parent UI, analytics, or URL params.

```tsx
<HistoryAuditTrail
  events={events}
  countLabel={`${events.length} events`}
  moduleSources={moduleSources}
  onModuleSourceChange={(selectedSource) => {
    console.log('Selected module source:', selectedSource);
  }}
/>
```

`onModuleSourceChange` is fired whenever the selected module changes, including when users select
`All Modules`.
