## Import

```ts
import { HistoryAuditTrail, HISTORY_AUDIT_RENDER_MODES } from '@gen2fund/gen2verse-ui-library';
import type { HistoryAuditTrailEvent } from '@gen2fund/gen2verse-ui-library';
```

## Quick start (rapid integration)

1. Install the UI library package in your frontend module.
2. Return audit entries from your backend using the `HistoryAuditTrailEvent` shape.
3. Pass entries to `events` and render in panel mode.
4. Verify search/filter and optional export with real module data.

```bash
npm install @gen2fund/gen2verse-ui-library
```

```tsx
import { HistoryAuditTrail, HISTORY_AUDIT_RENDER_MODES } from '@gen2fund/gen2verse-ui-library';
import type { HistoryAuditTrailEvent } from '@gen2fund/gen2verse-ui-library';

export function QuickStartAudit({
  events,
  onClose,
}: {
  events: HistoryAuditTrailEvent[];
  onClose: () => void;
}) {
  return (
    <HistoryAuditTrail
      renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}
      title="Activity History"
      countLabel={`${events.length} events`}
      events={events}
      onClear={onClose}
    />
  );
}
```

## States

- **Loading**: set `loading={true}` (and typically `events={[]}`) to show the loader.
- **Empty**: pass `events={[]}` to show the empty state.
- **Render mode**: use `renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}` (default) or
  `renderMode={HISTORY_AUDIT_RENDER_MODES.INLINE}`.

## Backend integration (entry contract + mapping)

`HistoryAuditTrail` is frontend-only and expects backend data mapped to `HistoryAuditTrailEvent[]`.
The key contract is: one entry per activity, globally unique `id`, and a valid `timestamp`.

```ts
// Example backend response contract (server DTO)
type AuditApiEntry = {
  eventId: string;
  sourcePath: string; // e.g. /capevent/configuration/1003
  actor: string;
  actionType: 'ADDED' | 'UPDATED' | 'REMOVED' | 'OTHER';
  subject: string;
  details?: string | null;
  changedFields?: Array<{ name?: string | null; from?: string | null; to?: string | null }>;
  metadata?: Record<string, string>;
  createdAtUtc: string;
};

// Mapping server response to UI library shape
const toHistoryAuditEvents = (entries: AuditApiEntry[]): HistoryAuditTrailEvent[] =>
  entries.map((entry) => ({
    id: entry.eventId,
    source: entry.sourcePath,
    username: entry.actor,
    auditEventType: entry.actionType,
    subject: entry.subject,
    details: entry.details ?? null,
    fieldChanges:
      entry.changedFields?.map((f) => ({
        fieldName: f.name ?? null,
        oldValue: f.from ?? null,
        newValue: f.to ?? null,
      })) ?? null,
    additionalDetails: entry.metadata
      ? Object.entries(entry.metadata).map(([key, value]) => ({ key, value }))
      : null,
    timestamp: entry.createdAtUtc,
  }));
```

Notes:

- `oldValue/newValue` and `fieldChanges[]` are both supported.
- Include `source` when you want module-level filtering/dropdown behavior.
- Keep timestamps in ISO format for stable sorting and formatting.

## Render modes

- **Panel mode (`renderMode={HISTORY_AUDIT_RENDER_MODES.PANEL}`)**: shows history icon, title,
  count badge, module dropdown (when multi-module), search, export, and close button.
- **Inline mode (`renderMode={HISTORY_AUDIT_RENDER_MODES.INLINE}`)**: shows module dropdown (when
  multi-module), search, export, and timeline grid only (no panel header/title/close button).
- The count badge automatically formats as `X of Y events` when filters reduce visible rows.
- `onClear` is intended for panel close handling (for example, parent hides the panel).

## Action style configuration (icon + color mapping)

Use `actionStyles` to override icon and colors per `auditEventType`. Use `defaultActionStyle` as fallback
for custom action types your backend may emit.

```tsx

/>;
```

## Multi-module usage

```tsx
import { HistoryAuditTrail } from '@gen2fund/gen2verse-ui-library';

const moduleSources = [
  '/capevent/package/10001',
  '/capevent/configuration/1004',
  '/capevent/driver-report/3521',
];

export function MultiModuleExample() {
  return (
    <HistoryAuditTrail
      title="Activity History"
      events={events}
      countLabel={`${events.length} events`}
      moduleSources={moduleSources}
      primaryModuleSource="/capevent/package/10001"
    />
  );
}
```

Multi-module behavior:

- Dropdown appears only when more than one module has events
- Dropdown item names are derived from source paths (for example, `configuration` -> `Configuration`)
- `All Modules` shows all events across configured sources
- Secondary module entries show color-coded badges; primary module entries do not
- Change rendering supports both `oldValue/newValue` and `fieldChanges[]` response formats
- First `moduleSources` item is used as primary if `primaryModuleSource` is not provided
- For related module data, pass all relevant entries in one response time window (same business action)

### `moduleFilterCallback` behavior

`moduleFilterCallback` is optional. By default, filtering is automatic and uses:

```ts
event.source === selectedSource;
```

Provide `moduleFilterCallback` only when your event source format needs custom matching
(for example, trimming trailing slashes, normalizing case, or mapping aliases).

```tsx
moduleFilterCallback={(event, selectedSource) =>
  (event.source ?? '').replace(/\/$/, '').toLowerCase() ===
  selectedSource.replace(/\/$/, '').toLowerCase()
}
```

### `onModuleSourceChange` behavior

Use `onModuleSourceChange` to react when users change the module dropdown selection.
This is useful for syncing selected module state with parent UI, analytics, or URL params.

```tsx
<HistoryAuditTrail
  events={events}
  countLabel={`${events.length} events`}
  moduleSources={moduleSources}
  onModuleSourceChange={(selectedSource) => {
    console.log('Selected module source:', selectedSource);
  }}
/>
```

`onModuleSourceChange` is fired whenever the selected module changes, including when users select
`All Modules`.

## Extend search and export with module-specific fields

Built-in quick search and export already include:

- standard activity/timestamp data
- `fieldChanges[]` values
- `additionalDetails[]` key/value pairs

Recommended extension pattern: send module-specific fields via `additionalDetails` so they are visible
in UI details, searchable in quick search, and included in export text.

```tsx
const events: HistoryAuditTrailEvent[] = [
  {
    id: 'evt-42',
    source: '/capevent/package/10001',
    username: 'SYSTEM',
    auditEventType: 'OTHER',
    subject: 'Distribution recalculated',
    details: 'Recalculation completed',
    additionalDetails: [
      { key: 'INVESTOR_CLASS', value: 'Class B' },
      { key: 'FX_BOOK', value: 'USD_HEDGE_01' },
      { key: 'ALLOCATION_BATCH_ID', value: 'BA-2026-02-17-003' },
    ],
    timestamp: '2026-02-17T14:25:11.000Z',
  },
];
```

## Troubleshooting

- **No rows shown:** verify `events` is non-empty and each item has unique `id`.
- **Wrong module filter results:** verify `source` values match configured `moduleSources` exactly, or provide `moduleFilterCallback`.
- **Unexpected sort order:** verify valid ISO timestamps (invalid values are pushed to the bottom).
- **Search misses module-specific info:** ensure custom fields are sent in `additionalDetails` or `fieldChanges`.
- **Export option is missing:** set `enableExport` and use activity/timestamp cells for context-menu export.
