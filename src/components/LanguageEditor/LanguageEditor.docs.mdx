import type { FieldDefinition, ValidationResult } from '@gen2fund/gen2verse-ui-library';

## Basic usage

```tsx
import { LanguageEditor } from '@gen2fund/gen2verse-ui-library';
import type { FieldDefinition } from '@gen2fund/gen2verse-ui-library';

const fieldConfig: FieldDefinition[] = [
  {
    name: 'fundName',
    displayName: 'Fund Name',
    type: 'Dimension',
    dataType: 'text',
    group: 'Identity',
  },
  { name: 'nav', displayName: 'NAV', type: 'Measure', dataType: 'number', group: 'Metrics' },
];

export function Example() {
  const [content, setContent] = useState('');
  return (
    <LanguageEditor
      fieldConfig={fieldConfig}
      content={content}
      onChange={setContent}
      onValidate={(result) => console.log(result)}
    />
  );
}
```

## States

- **Read-only:** set `readOnly={true}` so all toolbar buttons are disabled and the editing area is non-editable; token rendering is preserved.
- **Empty content:** pass `content=""` for a blank editor.

## Conditional Language Builder

The **Conditional Language Builder** is a modal dialog component that lets users build conditional blocks (`{{IF}}` / `{{ELSE IF}}` / `{{ELSE}}` / `{{ENDIF}}`) without typing the syntax. It is intended to be opened from the LanguageEditor toolbar (e.g. a “Conditional” or “# Conditional” button); the parent is responsible for inserting the returned string at the cursor.

**Import:**

```ts
import { ConditionalLanguageBuilder } from '@gen2fund/gen2verse-ui-library';
import type {
  FieldDefinition,
  ConditionalLanguageBuilderProps,
} from '@gen2fund/gen2verse-ui-library';
```

**Usage:**

- Control visibility with `open` and `onClose`.
- Pass `fieldConfig` (same as for LanguageEditor / Field Insert).
- On “Insert Language”, the component calls `onInsertConditional(conditionalText)` with the built string, then closes. The parent should insert that text into the editor at the current cursor position.

**Behaviour:**

- **Field:** Selected from `fieldConfig`; same list as in Field Insert.
- **Operators:** Options depend on the field’s `dataType` (text / number / date / boolean) per the Operators per dataType tables below. Value-less operators (Blank, Not Blank) hide the value input; “Between” shows two value inputs.
- **Value input:** Type-aware: text field, number input, date input/picker, or true/false for boolean.
- **Content per clause:** Each IF, ELSE IF, and ELSE has a content area (textarea) for the text to display when that branch matches. The built string uses this content between the condition tokens.

See the **ConditionalLanguageBuilder** stories for examples.

## Props

| Prop          | Type                                 | Required | Description                                                                                                                     |
| ------------- | ------------------------------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------- |
| `fieldConfig` | `FieldDefinition[]`                  | Yes      | List of field definitions. See Field configuration schema below.                                                                |
| `content`     | `string`                             | Yes      | Rich text with embedded tokens (conditionals and field references).                                                             |
| `readOnly`    | `boolean`                            | No       | When `true`, toolbar buttons are disabled and the editing area is non-editable; token rendering is preserved. Default: `false`. |
| `onChange`    | `(content: string) => void`          | No       | Called when content changes.                                                                                                    |
| `onValidate`  | `(result: ValidationResult) => void` | No       | Called when validation runs. See Validation rules below.                                                                        |

### Events

- **onChange** — After any content change; payload is the new content string.
- **onValidate** — When validation runs (e.g. Validate button); payload is `ValidationResult` (valid flag + optional errors array).

## Field configuration schema

Each field has:

| Field         | Type                                        | Required | Description                                                                                                                                                                                                                                             |
| ------------- | ------------------------------------------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `name`        | `string`                                    | Yes      | Unique id used in content (e.g. `{{IF fieldName ...}}`, `«fieldName»`).                                                                                                                                                                                 |
| `displayName` | `string`                                    | Yes      | Label in Field Insert dropdown and Conditional Builder.                                                                                                                                                                                                 |
| `type`        | `'Dimension' \| 'Measure' \| 'Boolean'`     | Yes      | Semantic type (Dimension / Measure / Boolean).                                                                                                                                                                                                          |
| `dataType`    | `'text' \| 'number' \| 'date' \| 'boolean'` | Yes      | Drives allowed operators and **value input behavior**: the value box in the Conditional Builder must accept only input valid for this dataType (e.g. number field → numbers only, date field → date picker or date input, boolean → equals true/false). |
| `group`       | `string`                                    | No       | Optional category for grouping fields in the Field Insert dropdown (e.g. "Identity", "Metrics").                                                                                                                                                        |
| `description` | `string`                                    | No       | Optional help text for the field.                                                                                                                                                                                                                       |

**TypeScript:**

```ts
type FieldType = 'Dimension' | 'Measure' | 'Boolean';
type DataType = 'text' | 'number' | 'date' | 'boolean';

interface FieldDefinition {
  name: string;
  displayName: string;
  type: FieldType;
  dataType: DataType;
  group?: string;
  description?: string;
}
```

**Value input (type-aware):** For each field used in a conditional, the value input next to the operator must respect `dataType`: text → text input, number → number-only input, date → date input/picker, boolean → equals with true/false. This applies in the Conditional Language Builder UI.

## Conditional Language Builder

The **Conditional Language Builder** is a modal dialog component that lets users build conditional blocks (`{{IF}}` / `{{ELSE IF}}` / `{{ELSE}}` / `{{ENDIF}}`) with field, operator, value, and content for each branch. It is intended to be opened from the LanguageEditor toolbar (e.g. a “Conditional” or “Insert conditional” button); the parent inserts the returned string at the cursor.

**Import:**

```ts
import { ConditionalLanguageBuilder } from '@gen2fund/gen2verse-ui-library';
import type {
  ConditionalLanguageBuilderProps,
  FieldDefinition,
} from '@gen2fund/gen2verse-ui-library';
```

**Props:** `open`, `onClose`, `fieldConfig` (same `FieldDefinition[]` as the editor), `onInsertConditional: (conditionalText: string) => void`. When the user clicks **Insert Language**, the component builds the conditional string and calls `onInsertConditional(text)` then closes. The value input is type-aware per field `dataType` (text, number, date, boolean); operators **Blank** and **Not Blank** have no value input; **Between** uses two value inputs.

**Usage:** Control visibility with `open` and `onClose`. On `onInsertConditional`, insert the returned string into the editor content at the current cursor position (handled by the parent LanguageEditor shell).

## Conditional syntax grammar

Pattern: `{{IF fieldName OPERATOR value}}content{{ELSE IF ...}}{{ELSE}}content{{ENDIF}}`. Order: IF → zero or more ELSE IF → optional ELSE → ENDIF. Conditionals may be nested; escaping for literal `{{` / `}}` is implementation-defined (e.g. `\{{`, `\}}`).

## Operators per dataType

Operators are determined by the field's **dataType**. Operators are shown in the dropdown with **lowercase labels** (e.g. "starts with", "greater than"). In the editor output, operators appear in **UPPERCASE** (e.g. `STARTS_WITH`, `IS_GREATER_THAN`).

### text (Dimension)

| Label (dropdown) | Key (in editor)    |
| ---------------- | ------------------ |
| equals           | `EQUALS`           |
| does not equal   | `DOES_NOT_EQUAL`   |
| contains         | `CONTAINS`         |
| does not contain | `DOES_NOT_CONTAIN` |
| starts with      | `STARTS_WITH`      |
| is empty         | `IS_EMPTY`         |
| is not empty     | `IS_NOT_EMPTY`     |

### number (Measure)

## Validation rules

- **Balanced IF/ENDIF** — Every `{{IF}}` / `{{ELSE IF}}` block must have a matching `{{ENDIF}}`.
- **Valid operator for dataType** — Operator in each clause must be allowed for that field's `dataType`.
- **Field references in fieldConfig** — Every field name in conditionals and in `«fieldName»` must exist in `fieldConfig`.
- **When:** At least on Validate action; host may also trigger on blur/submit. Result is reported via `onValidate` (e.g. `{ valid: boolean; errors?: Array<{ message: string; offset?: number; length?: number }> }`).

## Token rendering rules

Visual treatment must distinguish conditional tokens, field badges, and regular text. **Use the @platform/style library** for colors and fonts; do not hardcode hex values or font names. If the tokens or colors you need are not in @platform/style, request them from the platform team.

| Content type               | Appearance (via @platform/style)                                                                                           |
| -------------------------- | -------------------------------------------------------------------------------------------------------------------------- |
| **Conditional tokens**     | `{{IF ...}}`, `{{ELSE IF ...}}`, `{{ELSE}}`, `{{ENDIF}}` — use platform tokens for "conditional" (e.g. orange), monospace. |
| **Field reference badges** | `«fieldName»` — use platform tokens for "field badge" (e.g. gold/amber), italic, guillemets « ».                           |
| **Regular text**           | Default text color and font from theme.                                                                                    |
