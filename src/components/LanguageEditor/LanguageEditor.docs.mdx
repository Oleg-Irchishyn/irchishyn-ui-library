## Import

```ts
import { LanguageEditor } from '@gen2fund/gen2verse-ui-library';
import type { FieldDefinition, ValidationResult } from '@gen2fund/gen2verse-ui-library';
```

## Basic usage

```tsx
import { LanguageEditor } from '@gen2fund/gen2verse-ui-library';
import type { FieldDefinition } from '@gen2fund/gen2verse-ui-library';

const fieldConfig: FieldDefinition[] = [
  { name: 'fundName', displayName: 'Fund Name', type: 'Dimension', dataType: 'text', group: 'Identity' },
  { name: 'nav', displayName: 'NAV', type: 'Measure', dataType: 'number', group: 'Metrics' },
];

export function Example() {
  const [content, setContent] = useState('');
  return (
    <LanguageEditor
      fieldConfig={fieldConfig}
      content={content}
      onChange={setContent}
      onValidate={(result) => console.log(result)}
    />
  );
}
```

## States

- **Read-only:** set `readOnly={true}` to disable editing (toolbar and insertion disabled).
- **Empty content:** pass `content=""` for a blank editor.

## Props

| Prop | Type | Required | Description |
|------|------|----------|-------------|
| `fieldConfig` | `FieldDefinition[]` | Yes | List of field definitions. See Field configuration schema below. |
| `content` | `string` | Yes | Rich text with embedded tokens (conditionals and field references). |
| `readOnly` | `boolean` | No | When `true`, editor is non-editable. Default: `false`. |
| `onChange` | `(content: string) => void` | No | Called when content changes. |
| `onValidate` | `(result: ValidationResult) => void` | No | Called when validation runs. See Validation rules below. |

### Events

- **onChange** — After any content change; payload is the new content string.
- **onValidate** — When validation runs (e.g. Validate button); payload is `ValidationResult` (valid flag + optional errors array).

## Field configuration schema

Each field has:

| Field | Type | Required | Description |
|-------|------|----------|-------------|
| `name` | `string` | Yes | Unique id used in content (e.g. `{{IF fieldName ...}}`, `«fieldName»`). |
| `displayName` | `string` | Yes | Label in Field Insert dropdown and Conditional Builder. |
| `type` | `'Dimension' \| 'Measure' \| 'Boolean'` | Yes | Semantic type (Dimension / Measure / Boolean). |
| `dataType` | `'text' \| 'number' \| 'date' \| 'boolean'` | Yes | Drives allowed operators and **value input behavior**: the value box in the Conditional Builder must accept only input valid for this dataType (e.g. number field → numbers only, date field → date picker or date input, boolean → equals true/false). |
| `group` | `string` | No | Optional category for grouping fields in the Field Insert dropdown (e.g. "Identity", "Metrics"). |
| `description` | `string` | No | Optional help text for the field. |

**TypeScript:**

```ts
type FieldType = 'Dimension' | 'Measure' | 'Boolean';
type DataType = 'text' | 'number' | 'date' | 'boolean';

interface FieldDefinition {
  name: string;
  displayName: string;
  type: FieldType;
  dataType: DataType;
  group?: string;
  description?: string;
}
```

**Value input (type-aware):** For each field used in a conditional, the value input next to the operator must respect `dataType`: text → text input, number → number-only input, date → date input/picker, boolean → equals with true/false. This applies in the Conditional Language Builder UI.

## Conditional syntax grammar

Pattern: `{{IF fieldName OPERATOR value}}content{{ELSE IF ...}}{{ELSE}}content{{ENDIF}}`. Order: IF → zero or more ELSE IF → optional ELSE → ENDIF. Conditionals may be nested; escaping for literal `{{` / `}}` is implementation-defined (e.g. `\{{`, `\}}`).

## Operators per dataType

Operators are determined by the field's **dataType**. Display label and value (key) per dataType:

### text

| Label | Key |
|-------|-----|
| Contains | `contains` |
| Does not contain | `notContain` |
| Equals | `equals` |
| Does not equal | `notEqual` |
| Begins with | `startsWith` |
| Ends with | `endsWith` |
| Blank | `blank` |
| Not Blank | `notBlank` |

### number

| Label | Key |
|-------|-----|
| Equals | `equals` |
| Does not equal | `notEqual` |
| Greater than | `greaterThan` |
| Greater than or equal to | `greaterThanOrEqual` |
| Less than | `lessThan` |
| Less than or equal | `lessThanOrEqual` |
| Between | `inRange` |
| Blank | `blank` |
| Not Blank | `notBlank` |

### date

| Label | Key |
|-------|-----|
| Equals | `equals` |
| Does not equal | `notEqual` |
| before | `lessThan` |
| after | `greaterThan` |
| Between | `inRange` |
| Blank | `blank` |
| Not blank | `notBlank` |

### boolean

| Label | Key |
|-------|-----|
| Equals | `equals` |

## Validation rules

- **Balanced IF/ENDIF** — Every `{{IF}}` / `{{ELSE IF}}` block must have a matching `{{ENDIF}}`.
- **Valid operator for dataType** — Operator in each clause must be allowed for that field's `dataType`.
- **Field references in fieldConfig** — Every field name in conditionals and in `«fieldName»` must exist in `fieldConfig`.
- **When:** At least on Validate action; host may also trigger on blur/submit. Result is reported via `onValidate` (e.g. `{ valid: boolean; errors?: Array<{ message: string; offset?: number; length?: number }> }`).

## Token rendering rules

Visual treatment must distinguish conditional tokens, field badges, and regular text. **Use the @platform/style library** for colors and fonts; do not hardcode hex values or font names. If the tokens or colors you need are not in @platform/style, request them from the platform team.

| Content type | Appearance (via @platform/style) |
|--------------|----------------------------------|
| **Conditional tokens** | `{{IF ...}}`, `{{ELSE IF ...}}`, `{{ELSE}}`, `{{ENDIF}}` — use platform tokens for "conditional" (e.g. orange), monospace. |
| **Field reference badges** | `«fieldName»` — use platform tokens for "field badge" (e.g. gold/amber), italic, guillemets « ». |
| **Regular text** | Default text color and font from theme. |
